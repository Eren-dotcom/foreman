Foreman API

The primitives an agent framework needs: open a job, pre-authorise a budget, pull a chunk, and verify a payment from chain. Every mutating call broadcasts a real Chipnet transaction when one is valid; every invalid call is evaluated against the BCH VM and refused with the covenant rule that stopped it.

Same code path in three places: the CLI (scripts/*.mjs), this HTTP API, and the browser demo. The covenant is the source of truth — this server only builds transactions; it cannot make an invalid one valid.

Endpoints

POST
/api/pods
Open a pod. Body: { chunk, window, blocks }. Returns the pod address and its live chain state.
POST
/api/pods/:id/fund
Client pre-authorises budget into the covenant. Body: { satoshis }. Broadcasts.
POST
/api/pods/:id/deliver
Provider pulls chunks whole chunks. Body: { chunks, payload }. Broadcasts, returns a signed receipt (jobHash + payloadHash + txid).
POST
/api/pods/:id/steal
Demonstration: attempt an over-window pull. Body: { chunks }. Never broadcast — evaluated in the VM, returns { refused, explain: { rule, line, text } }.
POST
/api/pods/:id/early-refund
Attempt to reclaim before expiry. Refused by refund.not-expired.
POST
/api/pods/:id/close
Mutual close. Body: { chunks }. Broadcasts.
POST
/api/pods/:id/refund
Reclaim after expiry. Broadcasts only when the tip has passed the expiry block.
GET
/api/verify/:txid
Read a payment back off the chain, decode the outputs, and confirm the provider was paid the expected amount.
GET
/api/evidence
The recorded run: every step, every txid, every refusal — the same JSON the page renders.
GET
/api/health
Network and demo identities.

Refuse before spending

A receipt is written after money moves. A preceipt is written after a decision and before anything is built. Ask the guard first and a bad job costs nothing — no transaction, no fee, no relay.

POST
/api/pods/:id/intent
Ask whether an intent would be allowed. Body: { action, amount, payTo?, id? }. Always 200 — a denial is an answer, not an error. Returns { verdict: "pass"|"deny"|"needs-review", code, reason, effect, rules[], hash }. Ask again with the same id and you get the original preceipt back with duplicate: true, never a second decision. Actions: deliver, close, refund, fund.
GET
/api/preceipts
Every preceipt this session, newest first, plus the intent ids already executed. The agent's own decision log.

Reconciliation

The app keeps a ledger. These ignore it and rebuild settlement from the chain's real transaction history, then check one identity: funded = paid + fees + refunded + elsewhere + held. If it does not close to the satoshi the reconstruction is wrong and the response says so — it never prints a plausible gap.

GET
/api/reconcile
Every pod this session, rebuilt from chain. Totals include balanceToTheSatoshi, booksAgree and unbookedPayouts. Read-only.
GET
/api/pods/:id/reconcile
One pod: funding txids, spend txids, deliveries, closing txs, anomalies, and the exact transactions the ledger never recorded (unrecordedOnChain, unbookedPayouts).
GET
/api/rules
The covenant's rules, derived from the same RULES map used to explain refusals, with guard: true on the ones the pre-execution guard also enforces.
GET
/api/run.json
302 to /data.json — the recorded run, one shape, no second copy.
GET
/api/phases
The spend-path state machine, generated from the compiled artifact by scripts/phases.mjs.

Wallet connector (WizardConnect)

Nothing above requires a key on the server if the client brings their own wallet. The flow is: the server opens a wiz:// relay session, the browser renders it as a QR, the phone scans it, and the server then asks the phone to sign the funding transaction. The server re-checks the signature and the amount against the covenant before it broadcasts — a wallet that returns the wrong transaction simply gets rejected.

POST
/api/wallet/connect
Open a pairing session. Returns { uri, qr (inline SVG), connected, wallet }.
GET
/api/wallet/status
Connection state, wallet name, and the last protocol events (poll every couple of seconds while the QR is up).
GET
/api/wallet/utxos
Derived receive addresses and their live balances, so the page can tell you what the wallet can actually fund.
POST
/api/wallet/xpub
No phone? Paste an account xpub; the server derives the same addresses read-only.
POST
/api/pods/:id/fund-wallet
Build → sign on the phone over the relay → verify locally → broadcast. Body: { satoshis }. Returns { txid, walletCheck, spends, fee, change }.
GET
/api/pods
Every pod this session, with live balances — the dashboard reads this.
GET
/api/pods/:id
One pod, live.

An agent using it

const API = "http://localhost:4173";

// 1. the agent opens a job: 20,000 sat per chunk, 60,000 sat window, 24 blocks
const pod = await (await fetch(`${API}/api/pods`, {
  method: "POST", headers: { "content-type": "application/json" },
  body: JSON.stringify({ chunk: 20000, window: 60000, blocks: 24 }),
})).json();

// 2. it pre-authorises a budget. The money is not in a hot wallet.
await fetch(`${API}/api/pods/${pod.id}/fund`, {
  method: "POST", headers: { "content-type": "application/json" },
  body: JSON.stringify({ satoshis: 100000 }),
});

// 3. the provider does work, then pulls exactly one chunk
const paid = await (await fetch(`${API}/api/pods/${pod.id}/deliver`, {
  method: "POST", headers: { "content-type": "application/json" },
  body: JSON.stringify({ chunks: 1, payload: completion }),
})).json();

// 4. anyone can verify the payment from chain, not from the server's word
const proof = await (await fetch(`${API}/api/verify/${paid.txid}`)).json();
console.log(proof.matchesExpected, proof.paidToProvider);

// 5. before the NEXT pull, ask the guard. A refusal costs nothing and can be retried
//    with a smaller amount; the same intent id never produces a second decision.
const ask = await (await fetch(`${API}/api/pods/${pod.id}/intent`, {
  method: "POST", headers: { "content-type": "application/json" },
  body: JSON.stringify({ action: "deliver", amount: 1000000, id: "attempt-7" }),
})).json();
if (ask.verdict !== "pass") return planAround(ask.code);   // e.g. "deliver.window"

// 6. when the job ends, let the chain audit its own paperwork
const books = await (await fetch(`${API}/api/reconcile`)).json();
console.log(books.totals.balanceToTheSatoshi, "/", books.totals.pods, "balance to the satoshi");

Receipts

Every delivery returns a receipt so a provider can prove what it served and that it was paid:

{
  "jobHash":     "sha256(canonical job definition)",   // binds the receipt to the pod parameters
  "index":       2,
  "payloadHash": "sha256(the delivered work)",
  "txid":        "…",                                   // the real payment
  "paidSats":    "20000",
  "hash":        "sha256(all of the above)"
}

The covenant doesn't verify the payload — it enforces money, not truth. The receipt is the honest seam: the payer can challenge a payload hash, the provider can prove payment. A production version puts the payload hash in the chunk commitment so disagreement is visible on chain.
